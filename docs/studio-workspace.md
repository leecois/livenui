# Studio workspace

Studio is the focused component editor at `/studio`. Guides keep discovery, starting examples, essential controls and installation in reading order. Studio removes the repeated document navigation from the editing surface while retaining the Glass shell and its existing route underneath.

## Anatomy

The header identifies the current component, links back to its guide, names a saved preset, switches theme and copies the current React code. Compact headers use labeled icon actions. Theme changes retain the renderer and update the active component theme in exported code; explicit imported theme props are respected by the preview. At widths of at least 1100px, Components occupies 256px on the left, the live preview fills the center, and the 352px inspector occupies the right. Component links and starting examples scroll together in the left panel. Component links and starting examples use flat, left-aligned 44px rows with 4px gaps, 12px text insets and 8px panel insets. Unselected rows have transparent fills and borders; hover uses the neutral track and selection uses the accent gradient. Groups have 20px separation. Starting examples remain full-width native radios, including short lists of two or three; option count must not switch them into a segmented track. Customize / Presets / Code remains outside the inspector's scrolling content. Presets names, saves, loads and deletes configurations for the current component in this browser. The header Save preset action selects Presets, opens its inline form and focuses its name field.

From 700px to 1099px, preview and inspector remain side by side; Components opens as a native modal drawer. Below 700px, preview and inspector share the available height in two rows. Settings scroll independently, allowing a drag to update the visible preview. Component and example navigation remain in the drawer; Presets stays in the inspector. Escape closes the drawer and restores its opener. Changing a component or selecting an example closes it. The fullscreen outer dialog clips overflow, contains keyboard focus and keeps its header anchored.

Scrolling panels have no focus outline around their perimeter. Links and form controls retain their existing focus cues; panel focus does not add a new tab stop or change scrolling and drawer behavior.

The server-delivered shell opens its native dialog before hydration. Initial navigation and reload cover the document while the validated configuration fragment and SDK adapter load. Desktop component navigation is already available in the shell. Code copying and preset editing become available when configuration is ready.

Customize reuses the existing field dispatch and draft gestures. Essential settings come first; expanded settings retain Appearance, Motion and Interaction groups. JSON is an explicit button disclosure with validation next to the editor. Import/export and the API reference remain native contextual disclosures with full-width summary targets and trailing state chevrons. Import feedback stays directly below the transfer actions; its empty live region occupies no space. Code contains installation, package-manager choices, the configured React snippet and the agent prompt. Bright actions and selected pills retain the shared accent gradient with white text in both themes; contrast flags remain accepted design trade-offs.

Installation uses three compact npm/pnpm/Bun radio chips and a 44px icon-only Copy command action in one toolbar. The accessible group label remains available without repeating it visually. The complete command occupies its own row and wraps inside narrow inspectors. React code also wraps long lines while keeping local vertical scrolling. Copying preserves the original command/snippet text, uses tooltip and live feedback, clears feedback when the command changes and ignores late results for an older command. The existing package-manager state and renderer remain owned by the workbench.

Each task has one label. The header omits a tagline, component navigation omits explanatory prose, and Customize omits a repeated heading above Reset. Preview captions retain width and the interaction hint; playback state is shown by the action. JSON and transfer disclosures omit explanatory subtitles. Presets initially shows one New preset action and the saved list. The action opens a full-width name field above equal Cancel and Save actions, with 12px spacing. Enter saves; Escape or Cancel closes the form and retains the draft. Successful persistence closes it and restores focus to New preset; validation/storage failures leave it open. Browser-local storage is described through the field's accessible hint, Save tooltip and confirmation. Saved names wrap in flat rows beside a 44px delete target; an empty list adds no spacing. Newly opened forms and saved rows fade in for 160ms, with immediate display under reduced motion and no animated panel height. Code shows the command and snippet first, with alias, compatibility and component-specific requirements inside Integration notes.

## State and lifecycle

There is one active `usePlayground` owner and one central preview. Customize / Presets / Code changes inspector presentation without remounting the renderer or stopping microphone capture. Pause, Replay, component navigation and leaving Studio retain their explicit resource boundaries. Guides still unmount their preview on Install & Usage, stopping capture before returning.

The workbench keeps an in-memory snapshot for each component during the current Studio visit. It contains committed props, component variant, playback, JSON draft/disclosure, advanced search, preset-name draft, package manager and preview width. Returning to a component validates its committed props before restoring them. Numeric/color field text that has not committed is owned by the field and is discarded when its component unmounts. Snapshots never keep renderer instances, streams or pending file reads. Component navigation releases the departing preview and invalidates its pending imports.

An explicit example or configuration fragment takes precedence over retained state. Fragment imports use the existing `parseConfiguration` boundary and never become server query data. Reload starts from the URL configuration or component defaults. Only explicitly saved presets persist in `livenui-presets`; the temporary snapshots add no storage key or remote request.

## Owners and acceptance

[Studio composition](../apps/docs/features/component-library/views/studio-workspace.tsx) owns the fullscreen shell, responsive panel layout and inspector tabs. [Workbench](../apps/docs/features/component-library/views/workbench.tsx) owns temporary snapshots and preview width. [Playground state](../apps/docs/features/component-library/hooks/use-playground.ts) owns initialization, validation, configuration and export. Presentation belongs in [Studio styles](../apps/docs/features/component-library/styles/studio.css); all seven SDK adapters and registry contracts remain unchanged.

[Workspace browser checks](../e2e/studio-workspace.spec.ts) cover viewport geometry, independent scrolling, native drawer focus, keyboard tabs, renderer retention, component restoration, unapplied JSON drafts and entry/reload before hydration. Existing settings, width, microphone, handoff, examples, import/export and preset tests exercise the new anatomy. Run `bun run check` and `bun run test:ui` against freshly built production output, then inspect full-page desktop/mobile light/dark captures as required by [testing](testing.md). These checks use Chromium with software rendering and synthetic microphone input, not physical hardware or deployment.
