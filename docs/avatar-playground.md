# Avatar playground

The Bot avatars guide opens a complete local chat playground. Studio keeps its component editor and provides the same Chat playground action. Both presentations share the existing `usePlayground` configuration owner and native SDK adapter.

## Reference and scope

The public [Momo playground](https://feralui.dev/momo) was inspected in Chromium on 2026-10-07 at 1440px and 390px. Its complete composition has an examples/history sidebar, a full-height conversation with a centered character and grouped helper picker, a bottom composer, and a separate configuration sidebar. The helper picker and New bot belong only to the empty conversation. During conversation, a small character sits just above the composer's left edge; no bot selector remains in that scene. Examples choose a role automatically and open their own conversation. Replies can stream or appear instantly. On mobile, examples and Playground open over the conversation.

Liven UI follows that complete composition and interaction model. The owner selected a local interactive chat demo. Twenty original scripted examples, eighteen outfits assembled from retained native accessories, bot identities, conversation history, Stop, simulated availability and Stream/Instant replies work without chat requests, credentials or a backend. Appearance uses the existing semantic surfaces, spacing, rounded-full controls and accent gradient. Reference artwork, character assets and branding are not included. The retained SDK supports Idle, Working and Sleeping rather than the reference renderer's seven expressions.

## Full-height chat

- The native fullscreen dialog covers the viewport while retaining the Glass shell and route below it. The outer dialog clips overflow and never scrolls; sidebars and the message feed own scrolling. Wheel input over the character and focus changes must not shift the full-height layout or reveal space below it. Native modal behavior makes the covered interface inert. Component preview closes chat and returns to the same configuration; Chat playground reopens it with retained conversations and named bots. Leaving the workbench releases that local session.
- A scoped inline initializer in the server-delivered chat markup opens the native main dialog and its wide sidebars before the application chunks hydrate. This prevents the covered guide from flashing on navigation or reload. Layout effects take over dialog ownership and measure the root before paint, preserving the initial responsive geometry. Only the dialogs permit the expected imperative `open` attribute during hydration. The SDK preview remains lazy; initialization adds no timer, loading overlay or second configuration owner.
- The dialog root is its own inline-size container. At widths of at least 1100px, columns are 256px for examples, a flexible conversation, and 320px for Playground. Each sidebar scrolls independently below its 64px header. Below 1100px, both sidebars become native modal overlays with contained focus, Escape dismissal and opener restoration. Resizing changes presentation without replacing the main native avatar.
- Back to all components is a native `/agents` link with an 18px arrow and 44px target. At wide widths it precedes the logo in the fixed Examples header; compact layouts place it first in the conversation header. Only one Back link is visible in the active layout. The scrolling sidebar has no All components footer. Ordinary activation stops reply work and closes chat before navigation; modified clicks retain native link behavior. The server-delivered link is available before hydration. Below 550px, the conversation header uses 8px inline padding and 4px gaps so all 44px icon targets fit at 320px.
- Sidebar headings and contents use a shared 16px inline inset. New chat occupies the existing fixed toolbar with 16px space below the header; scrolling or focusing the list cannot press it against the divider or hide it. New chat, history and example rows use aligned 20px icon slots, 8px gaps and 13px labels. The wide Back target shares their icon center. Only conversation history and examples belong to the left scroll region, with 20px between groups and no extra margin before the first group.
- An empty conversation centers a 128px native avatar, Who's helping picker and New bot action. Its stage reserves that size while the preview loads, keeping the picker and heading in place. Shape thumbnails use neutral 24px loading dots without overlapping their labels. During conversation, the same renderer uses 64px and sits just above the composer's left edge. Replies use 24px native icons. The picker and New bot unmount during conversation. These presentation sizes do not change exported component size; size editing stays in the component editor. Working is a temporary demonstration state while a reply is pending; exported props remain the chosen component configuration.
- Helper selection uses a native auto popover with grouped options, role descriptions, a current-selection mark, ArrowUp/Down, Home/End, Enter/Space, Escape and opener restoration. Clicking outside dismisses it. Its bounds fit the viewport; resizing closes it. The selected helper applies a native accessory/color preset without changing shape or remounting the main renderer. Custom bots remain selectable in their own group.
- The message feed scrolls separately and follows replies while the reader is near its bottom. Enter submits, Shift+Enter adds a newline, and composition input is preserved. Input is limited to 2000 characters. Up to twenty conversations with forty messages each are retained in this workbench session.
- Stop, Offline, a new conversation, history selection, closing chat and teardown invalidate pending reply work. Each example opens a separate bounded conversation with its own helper configuration and active sidebar indication. Reselecting an example restores its conversation and configuration without adding a duplicate history row; custom conversations appear in Chats. Reply icons retain their original avatar props. Stream-to-Instant changes retain progress. Connection controls simulate availability; local-demo wording remains visible. User content is rendered as plain React text.

## Configuration and integration

The helper picker exposes eighteen native roles and up to twenty named bots created from the current configuration. Playground's Character section puts all twenty-two catalog shapes, an inline Outfit grid and Color together. Shape reuses the native thumbnail grid with eight featured options and inline expansion to all twenty-two. Outfit shows six native radio chips and expands inline to all eighteen options. It changes only native hat, glasses, headphones and bow-tie props, preserving shape, color, material and size. Unmatched accessory combinations display Custom outfit. A chosen option remains visible after collapsing the list. Six quick colors retain the exact editor and native picker. Activity and playback sit together; Chat demo separates simulated connection and reply modes from appearance. Those two-option choices use inset tracks beside 80px labels. Appearance & motion exposes the remaining native material, face, accessory and motion controls. Component size remains configurable in Component preview and Studio.

Customize and Code occupy equal halves of a 54px neutral strip in a fixed toolbar below the panel heading. Each native tab has a 44px target and an inset keyboard focus ring. The shared SelectionTrack moves a decorative gradient pill between the selected native targets in Activity, Connection, Replies and Customize/Code. It snaps for reduced motion and layout changes. The toolbar stays available while settings or code scroll. Outfit chips are separate rounded-full 44px targets in a two-column grid with 8px gaps and one inset keyboard focus ring. No settings menu covers the character. Each section retains the existing configuration owner and shared controls.

Playground's Code tab uses the existing code panel. Open in Studio transfers the validated current configuration. Get installation steps returns to the workbench's Install & Usage task. Closing chat stops its reply work and unmounts its scenes; the underlying component preview then mounts from the retained props and playback.

The component editor retains the preceding character workspace: preview beside a 384px controls panel at feature widths of at least 900px, stacked below that width, with current code and then starting examples. Shape radios show eight common native paused thumbnails, expand to all catalog shapes, retain an imported selection and preserve native keyboard selection. Each controls panel queries its own width.

## Ownership and verification

`views/avatar-chat.tsx` composes the chat and owns presentation/profile state. `hooks/use-avatar-chat.ts` owns bounded local conversation state and cancelable reply scheduling. `lib/avatar-chat.ts` owns scripted examples and native outfit combinations. Panels receive configuration/chat values and callbacks; they do not create configuration sessions. SDK imports remain in `previews/avatars.tsx`; no engine, public API, registry or infrastructure is replaced.

Run the gates in [testing](testing.md). `e2e/avatar-chat.spec.ts` verifies complete desktop composition, mobile overlays, focus/Escape, resizing, renderer identity, grouped helper selection, compact example avatars, absence of conversation selectors, independent example threads, restored helper configuration, streaming/cancellation, history, offline/instant modes, bot profiles, theme switching, code parity and absence of chat requests. Inspect its full-page empty, stopped, helper-picker, example and customized conversations plus mobile overlay captures in all four viewport/theme projects. `e2e/avatar-chat-settings.spec.ts` adds balanced tabs, contained focus, a fixed toolbar, direct outfit selection and expansion, retained native renderer and color, visible shape selection, code parity and full-page panel/expanded-choice captures. `tests/avatar-chat.test.ts` validates every outfit and helper preset against the retained component schema and checks scripted topics. Existing avatar-layout, mascot, settings, preview-width and integration journeys remain required; component journeys explicitly enter Component preview from the guide's initial chat. Browser checks use Chromium with software rendering and synthetic input, not physical devices or deployment.
