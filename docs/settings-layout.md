# Settings layout

Settings sit directly below the preview and before current integration code. Guides show essential controls; Studio adds advanced search, Saved and JSON. All views continue to use the same playground configuration owner.

## Reference and adaptation

The public [Eclipse customization panel](https://pro.reactbits.dev/docs/components/eclipse) was inspected in Chromium on 2026-10-06. It groups controls into a three-column grid with labels and values inside compact neutral rows, a nearby Reset action, numeric tracks and switches. The reference uses 32px numeric controls; Liven UI keeps its existing 44px native targets. No paid source, reference artwork or external palette is included.

The public [Blinds configuration](https://feralui.dev/blinds) was inspected in Chromium on 2026-10-07. It places short categorical choices beside aligned labels, keeps tracks sized to their contents and separates numeric dials into a three-column grid. There are no native selects in that panel. Its roughly 26px choice targets and 30px dials inform the anatomy only; Liven UI preserves 44px native targets, its numeric draft behavior and native selects for longer lists. Arrow keys adjust reference dials and double-click resets them; Liven UI keeps its explicit Default action.

Use the functional layout with local tokens: 20px panel insets, 12px field gaps, rounded-full neutral rows and bright gradient selection. Keep selected tabs/radio pills filled with `--gradient-accent` and white text. Checked switches use the same gradient with a white thumb. Accent contrast warnings remain accepted design trade-offs.

## Control contract

- Essential controls use one dense grid without category headings. Expanded Studio settings reveal Appearance, Motion and Interaction headings. Keep every field under the same grid parent with a stable key across expansion/collapse so invalid drafts survive. Sort the fields in DOM order to match the visual layout and keyboard navigation; advanced headings and dividers are grid items. Advanced search filters the same fields without creating another configuration store.
- Categorical rows place labels in a 112px column beside the value, with a 12px gap. Their controls stay compact rather than stretching every track across the field. Below 550px, labels move above controls with an 8px gap. Numeric, color and text fields keep labels above 54px shells with 4px insets and a 1px border. Selects and switches keep 44px targets; radio tracks add 4px insets around their 44px targets and can grow when choices wrap. Categorical controls precede the value grid, separated by a quiet divider when both kinds are present.
- Numbers combine an invisible native range over a thin neutral track and visible thumb with a separate exact input and a 44px Default action. Show the numeric value once. Dragging updates preview and code live; arrow keys step, Shift steps ten times, Home/End select the drag limits, and Escape or touch cancellation restores the value before the gesture.
- Curated presentation metadata in `lib/controls.ts` defines each numeric field's recommended drag window, step, unit and editing limits. These are not SDK API changes. Metal ring strength is bounded to 0–1; Text/Badge multiply strength by metal opacity and use a soft window. Image strength is bounded to 0–2. Speed can accept exact positive values outside its 0.25–3× drag window; custom values remain visible. The drag window stays visible beside the label; the step and keyboard instructions are available in the tooltip and accessible hint. Focus adds no content or height. Numeric, color, text and select shells show one focus ring, with no nested input ring. JSON/import parsing retains existing runtime contracts and can preserve values outside the control's window.
- Exact numeric and color input uses a local draft. Enter or blur applies a valid value; Escape restores the last applied value. Invalid drafts show adjacent text and preserve preview/code. Empty input or Default omits the prop so the SDK resolves its own default; Auto never injects a guessed fallback. Replacement by Reset, import, saved configuration, starting point or component variant discards old field drafts, even when the replacement contains the same value. Editing a draft invalidates pending asynchronous imports.
- Color controls combine a 44px native picker target, swatch and text entry. CSS colors, variables and color-mix stay intact for CSS-rendered fields. Orb tint accepts its native hex/rgb formats; avatar tint also accepts hsl. A picker selection intentionally replaces the expression with a hex value.
- Avatar size presets ascend from 32px to 96px with decorative size markers, retain numbers and add Custom for an exact number or CSS length. The Beam `size` prop is labeled Style because its values also select line and pulse treatments; exported API names remain unchanged. Fabric fur fields appear only for Fabric; Voice dot/line fields follow the selected look. Hidden values remain in configuration and export.
- Keep visible labels associated with their native controls. Radio fieldsets retain an accessible legend alongside their visible row label. Labels can wrap when space is limited. Native selects use one 44px face, a maximum width of 240px and one focus ring; the chevron stays decorative. They retain mobile and keyboard behavior.
- Boolean settings remain native checkboxes with a 44px target and a decorative switch track. A quiet On/Off status indicates the effective value; Auto identifies an omitted prop. Both label clicks and Space toggle the same configuration. Focus is visible around the track.
- Short typed choices of up to six options remain native radio groups on neutral tracks in both Guide and Studio. Groups with more than three choices span the whole row. Wrap choices without clipping their labels, targets or focus rings; custom values remain visible. Size presets plus Custom fit a single column.
- Place the compact Controls/Saved/JSON track beside the heading on wide containers and on its own row below 550px. Reset remains beside the heading. Guides omit the administrative tabs.
- Keep advanced discovery in the footer, separated by a quiet divider. Search only appears when advanced controls are expanded. Keep Saved input/action together and let JSON actions/help wrap at narrow widths. Validation feedback stays beside the panel.

Value columns follow the feature container: three at 900px or wider, two below 900px and one below 550px. Categorical rows use two columns at 900px or wider and one below; wide groups occupy a full row. See [design](../design.md) and [development](development.md).
